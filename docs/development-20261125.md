## 核心安全与恢复

- Work 身份包含分类、完整标题、季集与 variant；默认历史版本不改 ID 或路径。文件名确定性规则先于画质排名；标签不能覆盖明确身份冲突。
- 新保存先持久化意图。未知任务只恢复原候选，不按超时重提。确认非视频后也要先安全还原入口、确认精确云对象删除，才允许候选回退。
- 换源先保存、就绪、激活并读回新源，再以单事务发布 done/audit/ban/receipt。旧 leaf 的退休发生在提交之后。保存、激活或提交失败保留旧源；清理未确认返回 `cleanup_pending`，不递归删槽位或回收站。
- 非空、安全、精确版本 STRM 集合是激活、字幕落地及换源提交的前提。目录逃逸、符号链接、脏 variant 映射或未知用户保护均停止相关写操作。
- scout 池仅承担分享枚举；真正保存以主号重新取 token 和 fid_token。令牌桶在单进程内共享，不是跨服务/容器的全局速率保证。独立进程的整体调用预算须由部署者另行控制。
- 通知未配置即静默；心愿单入口有发送方白名单与幂等状态。测试没有发送外部通知。

完整转存、字幕、prefetch 与换源恢复约束见[实现说明](transfer-evolution.md)。搜索参数、真实 HTTP 诊断与不完整搜索语义见[插件指南](plugins.md)。

## 迁移与回退

发行过的 schema 1/2 迁移 SQL 保持冻结。schema 3 新增 variant、待上架、追更、通知、心愿单及换源提交凭证。冻结 v2 夹具回归验证迁移保留多集转存、审计、队列和映射；新增版本不覆盖默认集。

生产迁移必须停全部旧 writer，使用 SQLite backup API 取得包含已提交 WAL 的独立快照并校验。不能让 schema 2 程序与 schema 3 程序同时写同库，也不能只回退镜像后手改 user_version。回退涉及库时，先停 writer、保留新状态并明确备份后活动如何处理，避免混用旧主库与新 WAL。操作步骤见[升级与备份](quickstart.md#升级备份与回滚)。

## one 隔离验收环境

本工作区不挂载生产媒体、OpenList/Jellyfin 状态、主号 Cookie 或通知凭据。PanSou 使用固定 digest、loopback 8888 和 128 MiB 上限；VOD 验收实例使用本次构建的开发镜像、loopback 18099 和独立数据目录，256 MiB/128 pids、只读根、cap_drop=ALL、no-new-privileges。以运行报告记录实际构建与启动是否成功；配置文件本身不代表服务已运行。

健康、管理认证与 schema 检查只证明包和 HTTP/状态功能。搜索候选数、名称代理命中、部分短字节探针、Jellyfin PlaybackInfo、短段解码、全片观看、自然 cron 和用户设备分别取证，不互相代替。

历史开发运维工作区的 `evidence/`（不包含在公共发行、不是安装依赖）保存核心与宿主全套、门户场景、原 30 片搜索、5 片诊断及后续预算修复实测。原 30 片结果保留：P95 12.382 秒、30/30 partial、21/30 名称代理命中；不是 70% 真实召回率。后续快搜预算即使达成响应时限，也必须同时报告 partial、未执行变体与候选变化，不能推定 95% 召回达标。
