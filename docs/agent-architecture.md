# 点播架构与行为

2026-11-20 按最终源码、隔离回归和有限现场验证重写。运行版本、样本、计数及未覆盖边界统一见[本轮验收报告](/home/dong/.agent-context/verification/cinema-manual-2026-11-20.md)；操作步骤见[验证流程](../../hometheater/docs/agent-verification.md)，宿主作业见[影院架构](../../hometheater/docs/agent-architecture.md)。

## 组件与状态

app/main.py 提供 FastAPI 入口，server.py 协调搜索、保存和播放。app/quark_vod 是业务权威源，经 make sync 同步至 hometheater/scripts/quark_vod；七个宿主普通作业反向经 make sync-jobs 同步到 app/jobs。生产状态库位于 hometheater/data/quark_plays.db，锁位于 data/locks。容器使用 host 网络、只读 app 和 256 MiB 限额。同步后的代码与驻留进程版本分别确认。

| 入口 | 行为 |
|---|---|
| /health、/stats | 健康和状态摘要 |
| GET /pending、/play | 复用保存或发起搜索/保存，可读并激活后重定向，否则 503 |
| HEAD /pending、/play | 不发起新保存，响应不证明可播 |
| /preheat | 后台准备、保存及置顶，共享播放任务 |
| /media/{id}?v=…&skip=… | 从状态库和版本解析 MP4，不接受任意上游地址 |
| /clean | 清除伪装前缀，支持 HEAD、单区间、后缀 Range 和 416 |
| /api/admin/search-debug | 候选打分与名称提示，不转存 |
| /capability、管理台 overview | 创建、回读并删除唯一云探针，存在真实写入 |
| selfheal、reset、cookie 管理 | 按具体接口修改状态、入口或凭证 |

重定向编码非 ASCII Location。启动登记 STRM、处理超时任务并检查云写能力；后台自愈按配置运行。管理接口沿用当前内网范围，没有统一管理鉴权。

## 搜索与身份来源

panshare_matrix 每关键词最多三页；每节点默认二十四个不同详情页、调用最多三十，先去重再截取。下一页必须属于同源搜索路径，响应至多 2 MiB。每进程两个搜索槽、十二个 HTTP 槽，每节点三个详情线程；节点预算 22 秒，单 HTTP 最长七秒。预算限制后续调度，不保证整轮硬墙钟。

search_report 最多四个查询变体，使用规范片名、季号、年份及原名。同一分享合并标题、来源和提取码。v3 缓存完整非空三十分钟、partial/空四十五秒，内存最多 128 条，磁盘原子替换，缓存命中仍过滤已知死链。

电影/剧集、年份、季集、动漫/真人、数字续作和特别篇先作身份门槛，再比较相关度和画质提示。后续季允许受约束的该季年份；电影重拍版保持年份约束。门户原名来自 TMDB；播放/审计仅从类型、标题、年份匹配且无符号链接的作品 NFO 读取 originaltitle，文件至多 128 KiB，不改变存储身份。

| 搜索结果 | 协调器状态 |
|---|---|
| partial 且无合格候选 | search_incomplete |
| 完整搜索无合格候选 | source_unavailable，仅表示本次限定搜索范围 |
| 搜索异常 | search_unavailable |
| 保存或确认均失败 | transfer_failed，partial 时仍保留搜索未完成说明 |

## 实际文件身份选择

候选必须使用真实枚举文件的 file_name 和同一 relative_path，不得用另一个搜索结果或无关联目录替它补身份。先核对显式年份、路径季号与文件季号，再精确选择目标集；支持 S01E01、S01.EP01、EP01 及数字集名。多个 EP、集数区间和显式不同季集不能被截断后误认为单集。

通常从 basename 核对作品和 NFO 原名。若 basename 仅有数字集名或无法识别的拉丁译名，可从同一路径的强作品父目录继承身份：目录必须以完整作品核心开头，边界正确，剩余内容只允许实现中列明的年份、画质、语言和剧类元数据。目录显式年份全部一致；模糊包含、数字续作、真人版本或另一个作品不满足条件。嵌套的明显冲突中文目录、Anime/Movie/Part 等英文版本目录及可判定数字续作不能被精确祖先目录覆盖。

英文译名回退还要求集号之后只有明确技术元数据，不能丢弃 Anime/Movie、Part、另一作品等后缀。正常匹配分支同样拒绝显式版本/作品后缀及多集冲突。电影维持独立多正片保护，不通过此剧集目录规则按最大体积猜选。

这是可靠目录上下文规则，不是翻译证明：任意未知英文作品混入精确目录，仍可能无法语义识别。缺少强父目录时未知译名继续拒绝。新增命名形式必须先加真实结构及冲突负例，不能扩大为“父目录含目标就接受”。

本轮真实分享验证了《庆余年》中文目录下的英文 S01.EP01 和《各取所需》精确目录下的 01.mp4。昨天《各取所需》“缺集”由旧选择器误判，结论已撤回，生产仅条件恢复一条受影响记录。不能据此推断其它未枚举分享的可用性。

## 画质证据

quality.py 的 verified 始终为 false。优先检查尺寸与明确低分辨率，再看 4K/2160/UHD 名称。3840 宽且高至少 1600 可覆盖裁切宽银幕；2160×1080 不算 4K。目标文件的低分辨率证据覆盖分享宣传，体积、HDR、DV、REMUX 均不能单独证明 4K。unknown 不证明 HD，历史审计字段 valid_hd 也可能只是“目标存在但未获得4K提示”，不能当作实测高清。流宽高、解码与设备观看各自验收。

## 单文件保存与播放

Work 为分类、保留年份的标题、季、集；电影 0/0，剧集季集为正，S00 暂不支持。旧无年份身份必须有唯一映射证明。同身份共享 Future，同季跨进程锁；四工作线程、最多十六待处理任务，请求等待到期不取消后台保存。

依次复用 done、恢复不明保存意图、尝试精确目标锁源，再尝试最多八个搜索候选。锁源展示标题不重新打分，实际文件仍走身份选择器。仅保存一个 fid 到确定性 vod_<hash> 目录；枚举最多 1200 条、六层。多个电影正片无法确认身份时拒绝按体积猜选。同身份版本先比较分辨率提示，再比较大小。

保存和删除使用 /夸克网盘/点播，读取使用 /夸克/点播。提交前持久化 save_target、save_started_at、task_id；结果不明先回查原任务/目录，明确失败才允许重提。官方回读名称/大小后登记 done 和清理队列。读取通道未就绪保留 done，不激活其它集；done 不等于可播。普通 inspect_share_video 有独立请求预算，404 不足以永久判死。

_finish 核对短 Range、前缀和入口激活。STRM 稳定为 /play，r 仅供身份反查，实际路径来自状态库。原子写保留权限/所有者，同内容不刷新。解析缓存三十秒、最多 64 身份，命中核对 done ID/路径，失败不缓存。

MP4/M4V/MOV/MP41 走 /media：512 KiB 块、24 MiB 总缓存、五分钟 TTL/LRU、四个上游并发；客户端最多三十二连接、等待十秒，每次输出 128 KiB，断连释放槽。版本包含记录/路径/大小，旧版本拒绝复用。其它媒体走 QuarkTV，PNG 前缀走 /clean，没有 BMP 专用保证。不使用曾触发 OOM 的 interleaved_read=0；单次测速不能证明任意文件速度。

## 两层片源审计

根目录巡检按分类、标题、季、分享 SHA256 排序，data/source_lock_cursor.json 持久记录位置，不落原始分享地址。可读只证明根目录存在，不更新分集 checked_at。未知保留锁源；明确取消、过期或完整空分享才废弃并寻找覆盖原目标集的替代源。单组异常计 unknown/errors 后继续；failed_dead 仅表示本次未补齐，不表示全网无源。

文件审计复用实际递归选择器，每组至多五百个目标。一天内有效证据可复用；强制或过期核验先检查最多两个旧源，再检查最多六个新候选，分享去重。旧源无需当前搜索仍能搜到；所有目标已有4K文件提示可跳过搜索，仅部分集命中不算完整覆盖。已保存电影的 saved 捷径不重新证明云文件可读。

只有完整枚举、身份选择可靠且目标确实不存在，才将所选集设 not_found/has_quark_source=0；不修改其它集、不全局拉黑分享。枚举、网络、鉴权异常保留旧证据和时间。选择器缺陷导致的历史误判须通过原分享重新枚举，再做精确条件修复，不能批量重置。

文件审计通过独立 data/source_audit_cursor.json 按作品/季轮转。两个游标互不替代：实际已开始的尝试推进，包括未知、空结果、异常；预算耗尽且尚未开始的不推进，到末尾回绕。游标经唯一临时文件、fsync 和原子替换，权限 0644。宿主 night 的根目录阶段有局部预算和批量上限，不能挤占后续目标文件阶段；两阶段均受全局预算约束。

## 维护保护与精确删除

playback_access 证明解析请求，不是设备观看。维护保护六小时近期访问、用户收藏/已看/观看进度及手动置顶；Episode 按 SeriesName 保护整部剧，归属未知停止。普通播放不永久置顶，不预热下一集。

Jellyfin 保护数据库缺失或不可访问时，get_protected_titles 与空闲守卫均停止维护；凭证缺失、保护查询失败、Sessions 响应异常或播放中同样停止，不能视作空库/空闲。隔离业务 fixture 必须显式替代外部空闲守卫，并独立回归守卫的失败保护，不能靠临时库不存在绕过检查。在线数据库使用普通 mode=ro 读取 WAL，不用 immutable，不直接写 Jellyfin 库。

selfheal 逐叶检查 live 与有路径 done，校正 done 无路径。鉴权、网络、分页异常是未知。取得独占片库锁并确认空闲后重新核验缺失，先恢复入口，再提交 cleaned；云对象删除失败不报成功，共享目录及未到期其它集保留。

配额可读时使用账号 85%/70% 水位，点播不足 200 GiB 不淘汰，单轮约30%护栏；容量未知退回点播 2 TiB/1 TiB 固定阈值。不完整枚举不得驱动淘汰，dry-run 仍会读取真实服务。独立 cleanup 获取维护锁后仍核对片库/会话；--enforce-quota 仅处理错配/配额，普通执行再处理到期队列，均不清理 Jellyfin 图片。

图片清理由宿主日更在本次扫描确认完成后 strict 执行，要求数据库引用与文件枚举完整，失败不得记作清理完成；权限/default ACL 和恢复步骤见验证流程。回收站不处理。

## 本轮验证的范围

本轮包含手动真实扫描、图片清理 Canary、配额读取，以及 night/daily 隔离编排与真实旧分享有限复验，详情统一引用验收报告。隔离任务对外部服务和 call_llm 使用显式 fixture/当前会话人工答案，字幕检查覆盖格式结构、输出白名单、失败重试与幂等；不调用定时任务原有 AI 模型。

这些结果不等于完整 cron 运行周期、原模型生成输出或全库所有视频验证。部署后健康、接口、代码加载及选定真实播放结果分别留证，不能用离线通过替代现场验收，也不需要等待原周期才执行已获授权的手动检查。
