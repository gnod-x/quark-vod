# 本机点播适配边界

本文只描述 dong-server 家庭影院 checkout 如何运行公共 Quark-VOD 内核。独立用户
先读[公共架构](architecture.md)、[安装指南](quickstart.md)和[插件指南](plugins.md)。
本文引用的 `../hometheater` 路径只在两个相邻仓库同时存在的本机 checkout 中有效，
不会随公共 wheel 或源码包发布。

## 权威源与启动

- `app/quark_vod` 是公共内核的权威源，`app/main.py` 暴露 FastAPI，包内
  `static/admin.html` 是管理台。影院 checkout 的 `scripts/quark_vod` 是同步副本，
  同步入口和宿主作业边界见相邻影院的
  [CLAUDE.md](../../hometheater/CLAUDE.md)。
- 本机使用相邻仓库的 `quark-vod.compose.yml`。它以 host 网络运行、使用本机适配的
  UID/GID、只读根文件系统和只读 `/app` 源码挂载，持久写入仅落到显式配置的数据、
  日志和影院目录。公共 Compose 的默认地址、UID 和卷布局不能直接当成本机事实。
- cron、systemd 和手工宿主作业统一经
  [`scripts/run_vod_host.py`](../../hometheater/scripts/run_vod_host.py) 启动；
  入口、TARGET 和调度锁以[本机迁移说明](../../hometheater/docs/vod-host-migration.md)
  为准。不要在默认工作目录直接运行宿主脚本，否则可能把状态写入错误位置。

## 配置与凭据

运行参数和凭据层分离。宿主启动器只在显式 `--env` 指向的 `.vod-runtime.env` 中读取
运行参数，进程环境优先；需要沿用已有凭据时，再由 `VOD_ENV_FILE` 显式指向原凭据
文件。不会自动扫描当前目录或 HOME 下的 `.env`，也不会展开 `${...}`。

本机私有搜索 JSON 和管理令牌放在配置目录中，运行容器挂载整个目录，以便原子替换
后的 inode 对容器可见。节点数量、地址和名称属于本机 profile，不能写成引擎固定的
“五节点”。搜索字段、热加载和 trusted provider 行为以[公共插件指南](plugins.md)
为准；错误配置继续使用最后有效快照。

写挂载和播放挂载可以不同。当前本机适配通常以夸克写路径保存、以播放路径读取，
但实际值必须来自 runtime 配置，不应在宿主脚本里硬编码。Cookie、OpenList/Jellyfin
凭据、AI token 和管理令牌只通过环境或 secret file 传入，不出现在仓库、命令行、日志
和页面持久存储中。

## 搜索、身份与转存

本机搜索与公共内核使用同一个不可变配置快照；最多四个关键词变体共享该快照。节点
请求、响应体、页数、详情、并发和整组预算均有界。`configured=false`、`partial=true`
和配置错误分别表示未配置或本轮未完成，不能对用户说“全网没有资源”。当前 profile
的节点数和可用性需要从实际 `search.json` 与管理状态确认。

候选选择先核对作品身份，再排序画质：作品、年份、电影/剧集类型、季集、版本和
相同 `relative_path` 必须一致；目录名只能在满足强作品证据时补足弱文件名，不能覆盖
年份、季集、续作或特别篇冲突。4K 名称、文件大小、媒体宽高、解码结果和设备观看
是不同证据，`unknown` 或 `valid_hd` 不能当作实测 4K。

转存生命周期遵循以下顺序：

1. 复用已确认的 `done`，或先恢复带 `save_task_id` 的不明保存意图。
2. 再尝试已锁定且身份已核验的分享，然后才进行有界公共搜索。
3. 只保存选中的文件到确定性目录；通过夸克权威目录和播放侧读取检查后才提交
   `done`。OpenList 列表缓存或刷新结果不能单独证明文件存在。
4. 读取侧未就绪时保留可恢复状态，不盲目重复保存。失败的变更不能推进保存或清理
   状态；夸克回收站不属于本机维护范围。

## Jellyfin2 与播放

独立模式不要求门户预建片库：读取通过后返回已验证的播放 URL，也不创建或修改 STRM。
本机 Jellyfin2 模式必须激活已有的稳定 STRM 映射；映射缺失、路径不一致或激活失败
都应报告为集成失败，不能伪装成资源不存在。

STRM 只指向稳定的 `/play` 入口，远端路径从状态库按精确身份解析，不能信任客户端
任意路径。MP4 请求在满足条件时会经过 `/media` 的有界 Range 缓存和连接槽；其他
媒体可能走播放挂载直链或 `/clean` 清洗路由，路由由请求和上游 URL 决定，不按扩展名
做绝对承诺。Range、后缀 Range、416、HEAD、断连和长距离 seek 都要分别回归；不能
用健康检查代替实际读取和解码验收。

公开 `/clean` 只接受配置 OpenList 的下载路径；重定向目标必须解析为公网地址，连接
固定到已检查的地址并保留 TLS 主机名，同时不继承环境代理。它是受网络边界保护的
流式代理，不是播放器用户认证系统。管理 API、统计、能力和预热接口统一需要 Bearer；
`/health`、播放器入口和清洗入口的认证边界以[安全说明](../SECURITY.md)为准。

## 宿主作业与维护

本机门户、Jellyfin2 保护数据库和宿主定时作业属于 hometheater 项目，不属于公共包。
宿主作业的路径、调度锁、片库锁、服务重载和回滚要求见[影院架构](../../hometheater/docs/agent-architecture.md)
与[迁移说明](../../hometheater/docs/vod-host-migration.md)。公共内核的维护仍必须：

- 持有调度/片库锁，并确认保护库、会话、用户状态、收藏、观看进度、置顶和近期访问
  可读；任一关键状态未知就停止。
- 先恢复对应 pending/save intent，再按精确身份处理云对象；删除未确认时保留原路径
  和可重试记录，不能因一次枚举失败把对象当成不存在。
- 使用 SQLite `mode=ro` 读取在线 WAL，及时关闭连接；不直接写 Jellyfin 库，不用
  `immutable`，不整库覆盖升级后产生的新状态。
- 日更、夜间和自愈任务只在成功条件满足时写完成标记。夸克回收站不做清理，也不以
  全库 prune 代替针对性维护。

## 变更与验收

公共内核的代码、配置或架构变化先按公共测试和打包流程验证，再同步到影院副本；
影院适配变化还要按宿主契约重跑配置、状态保护、部署和播放验证。磁盘上的同步副本
不等于正在运行的进程已加载，重载或重启后必须核对实际版本和挂载路径。

至少分开记录以下证据：隔离单元测试、源码树外 wheel 安装、受限容器启动、管理 API
鉴权、OpenList 读取、STRM 激活、Range/seek、完整解码和真实设备播放。任何一层失败
或未知都不能标记闭环。验收材料和回滚备份保存在本机运维目录，不把真实 Cookie、
数据库、媒体路径或私有快照复制到公共文档。
